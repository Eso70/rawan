# Rawan

Rawan is an author-focused creative writing and worldbuilding platform under active development. The backend provides authentication, author profiles, user access controls, health checks, and the Project → Book → Chapter → Scene manuscript hierarchy. The website has a public landing page; the author workspace is still a starter application and the worker is a placeholder.

## Structure

```text
apps/
  website/       Next.js public website
  app/           Next.js author workspace
  api/           NestJS API
  worker/        Background worker placeholder
packages/
  database/      PostgreSQL schema, migrations, and generated Prisma client
  types/         Shared TypeScript domain/API types
  ui/            Reserved for shared UI
  utils/         Reserved for shared utilities
docs/            Project documentation
```

The stack uses TypeScript, ESM, pnpm workspaces, Turborepo, Next.js/React/Tailwind, NestJS, PostgreSQL, and Prisma **7.10.0**. Redis/BullMQ and Linux deployment with Caddy/PM2 are planned, not configured.

## Prerequisites

- Node.js **24.21.0**, as specified in `.nvmrc`; the Node 24 and 26 release lines satisfy the declared engines.
- pnpm **11.8.0**, pinned in the root `packageManager` field.
- PostgreSQL and a local `rawan` database for migrations and running the API. Building and the default CI checks do not require a live database.

Use your preferred Node version manager, then install the pinned package manager if needed:

```sh
npm install --global pnpm@11.8.0
```

## Install

After cloning your repository, run all workspace commands from its root:

```sh
cd rawan
pnpm install --frozen-lockfile
```

The repository uses a single root lockfile and Git repository. Do not initialize Git or run independent package installs inside the apps.

## Environment and database

Create these local files from their committed examples:

- `apps/api/.env.example` → `apps/api/.env`
- `packages/database/.env.example` → `packages/database/.env`

PowerShell:

```powershell
Copy-Item apps/api/.env.example apps/api/.env
Copy-Item packages/database/.env.example packages/database/.env
```

Linux/macOS:

```sh
cp apps/api/.env.example apps/api/.env
cp packages/database/.env.example packages/database/.env
```

Do this only when the destination files do not already exist. Set your own PostgreSQL credentials in both files and use the same database URL. Generate a random API JWT secret:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

The API supports `DATABASE_URL`, `JWT_SECRET`, `NODE_ENV`, `PORT`, and `CORS_ORIGINS`. The database package uses `DATABASE_URL` for migrations. The frontend and worker currently require no environment templates. Never commit local environment files; `.env.example` contains placeholders only.

Create the PostgreSQL database through your local database administration tool, then apply the committed migrations:

```sh
pnpm db:validate
pnpm db:generate
pnpm db:deploy
```

Use `pnpm db:studio` to inspect your local database with Prisma Studio. It requires the database package's configured PostgreSQL connection.

`db:deploy` applies existing migrations without creating new ones. Use `pnpm db:migrate` only when deliberately changing the schema and creating a development migration; commit the resulting migration files. Client generation never applies migrations. The generated client is ignored and regenerated by database builds; schema and migrations belong in Git.

## Development

```sh
pnpm dev
```

Turborepo builds shared dependencies before starting dependent apps. Local defaults:

| Service          | Address                        |
| ---------------- | ------------------------------ |
| Website          | `http://localhost:3000`        |
| Author workspace | `http://localhost:3001`        |
| API              | `http://localhost:3002/api/v1` |

An explicit API `PORT` overrides its default; ensure your local ports do not collide. The worker currently only logs its startup. You can run one workspace with `pnpm --filter @rawan/api dev`, for example, after building its shared dependencies.

See [API documentation](apps/api/README.md) for endpoints, validation, authentication responses, and production environment rules.
See [manuscript domain documentation](docs/manuscript-domain.md) for ownership, hierarchy routes, ordering, content, and the new migration.

## Checks and builds

```sh
pnpm lint
pnpm typecheck
pnpm build
pnpm test
pnpm test:e2e
pnpm format:check
```

Lint covers all six active workspace packages: the existing Next.js ESLint configurations handle the frontends, and shared Oxlint configuration handles the API, worker, and handwritten shared-package code. Generated Prisma code is excluded. Explicit `any` and unhandled promises are errors in Oxlint. Typecheck covers all six packages; Next.js route types and the custom Prisma client are generated as needed. API typecheck also builds the API because HTTP tests import its compiled application. Build compiles all six packages in dependency order and regenerates Prisma.

`pnpm test` builds the API and shared dependencies before running Vitest unit tests, so it works from a fresh clone. `pnpm test:e2e` builds and exercises the compiled API with isolated persistence; neither command requires PostgreSQL. Direct API unit-test commands require the shared packages to have been built first.

Prettier is the single formatter, configured at the root. `pnpm format` formats maintained source, configuration, and documentation; `pnpm format:check` checks them without modifying files. Existing API single-quote and frontend double-quote conventions are preserved. Generated files, local secrets, framework-managed instructions, lockfiles, and historical reports are excluded. Oxlint and Prettier are root development tools shared by the workspaces; each frontend retains its existing ESLint setup. No formatting plugins or additional lint ecosystems are required.

`pnpm --filter @rawan/api test:database` is an optional live PostgreSQL smoke check that creates and removes temporary test accounts. Use a development/test database. It is not run in CI. GitHub Actions runs frozen installation, Prisma validation, formatting, lint, typecheck, build, and database-independent unit/HTTP tests on pushes and pull requests.

`packages/database` owns the schema, migrations, and Prisma exports. `packages/types` holds existing domain types and public JSON contracts; API-only JWT/request types stay in the API. `packages/ui` and `packages/utils` are empty reserved directories, not active packages. Add code there only when multiple workspaces actually share it. TypeScript versions currently differ between the existing Next.js, NestJS, and shared-package setups; each has strict checking, and this baseline preserves their working versions.

## Repository safety

Root ignore rules exclude credentials, local certificates, dependencies, generated clients, builds, caches, logs, and editor state. Review staged files before every commit; ignoring a file does not remove it from earlier history. Local assistant resources installed under `packages/database` are retained locally and excluded from Git.
