## Cumulative changes and gaps

- Batch 1 established compact chrome, atmosphere, contextual support and tutorial steps 2–5. Batch 2 adds step 1, restart discovery, full property rows, two-panel composition, canvas contents, map regions/markers, choice onboarding and visible theme/type variation. Earlier observations remain valid within their images.
- Repeated patterns: atmosphere (4/5/12–26/28/29), rounded panels (1–3/13–26), compact tool controls (4/12/18/20–23/27–29), portrait-plus-document (13–19/21–27/29), map pairing (23–26/29), tutorial targeting (14–18).
- Unresolved: actual mobile layouts, a full timeline editor, full relationship graph controls/layout, active property-editing menu, keyboard behavior, label collision logic, save failures, and true collaboration. A miniature graph in 20 is not a complete graph interface.
- `vvd29.png` omits browser chrome while several others include it; compare application bounds, not screenshot outer height. The warm 4 and cool 28 are separate contexts; do not infer a theme switch sequence.

## How to add another batch

Append a new batch table with only newly received images and a change note. Repeated filenames retain their original entry; if contents changed, record a version and provenance rather than silently replacing evidence. Inspect each new image before marking it analyzed. Add supporting IDs to existing pattern sections and preserve conflicting observations with their source IDs. Reassess capability claims against current DTOs/OpenAPI, then update proposal status and open decisions. Count unique inspected screenshots, never filename ranges. Ask for a resend only if inaccessible evidence is necessary to resolve a decision. Do not implement from a batch update.
