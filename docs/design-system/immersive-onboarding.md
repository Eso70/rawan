## Audit and plan

The existing five steps, controlled OnboardingFields, grouped native InterestPicker and shared native controls already separate presentation from persistence. Keep those questions/options, conditional visibility, validation, saved revisions, authentication, APIs and routing unchanged. Existing age-removal behavior remains unchanged. No backend/schema or other page redesign is needed.

1. Create original, atmospheric architectural/natural background images using the built-in image-generation skill. Keep prompts/provenance with the assets; introduce no third-party reference imagery. Optimize local responsive files, keep loading independent of forms and provide a static navy fallback.
2. Add a feature-owned reusable background component and small pure transition reducer. Load only requested/previously loaded scenes, crossfade after readiness, ignore late loads from an old step, and fall back safely on failure. Reduced motion removes all crossfades.
3. Restyle the existing shell into a vertically centered, fluid composition: minimal brand/leave header, subtle progress, large centered Lora question, narrow form measure, translucent native inputs/selects and compact selected chips. Move sign-out into the footer without changing its POST action.
4. Keep related interest groups together, with two columns for Both only where space permits. Expanded/long content must grow naturally and scroll; no fixed-height form or clipped submit/error controls. Retain labels, disclosures, native keyboard behavior and visible focus.
5. Test the transition reducer, asset delivery/failure and unchanged form behavior. Run website checks after the background system and redesign, then root checks and local registration/persistence/routing integration. Browser-check desktop, tablet, 320/390px, keyboard/focus, responsive selections, refresh/Back and reduced-motion behavior where tooling permits.
6. Update the onboarding design reference and current component/responsive/accessibility guidance with actual behavior and verification limits. Preserve existing unrelated source files byte-for-byte.

The named Quiet Literary Studio skill remains unavailable. The current Rawan design-system documentation and source are the available visual authority. No new reference attachments were supplied with this message, so the implementation follows the written direction and earlier conversation references without copying their artwork/layout/branding.

Run from the repository root:

```powershell
pnpm lint
pnpm typecheck
pnpm test
pnpm build
node apps/api/test/run-setup-validation.mjs
$env:SETUP_LOCAL_HTTP_TEST='true'
node apps/api/test/setup-routing-local-smoke.mjs
Remove-Item Env:SETUP_LOCAL_HTTP_TEST
```

The database runner is loopback-only and creates/removes dedicated disposable databases. The running-server suite requires the existing local API/website and cleans up its own synthetic fixtures. Do not reset the application database. Browser fixtures used for visual QA are signed out and removed after testing.

For manual design review, use a new local test account at `/login`; only unfinished new accounts see `/onboarding`. Walk through all five steps, try each purpose, expand chips, Tab/Space/arrow through native controls, exercise Skip/Back/refresh and complete, then sign in again. Check 320/390px phone, 768px tablet, desktop and short heights. With the OS reduced-motion setting enabled, confirm scenes change without crossfade and questions do not animate. Verify using a screen reader separately. Full interaction/validation steps remain in [the onboarding guide](../onboarding-guide.md).
