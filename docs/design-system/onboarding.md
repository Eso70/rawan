Every form screen renders `OnboardingContinue`, including the final Finish setup label. Its `components/onboarding-action.module.css` recipe composes `components/ui/glass-button.module.css`, the existing Google/Email sign-in button style, with compact sizing; completion/recovery links compose that same recipe. Section styles cannot alter its size, font, padding, corners, border or fill. The server still stores five steps: Welcome, Purpose, Interests, Preferences and Begin. Interests has two local screens when categories are selected, so the complete visible flow can have six screens. No database schema, API contract, role policy, authentication or redirect change is introduced.

## Interest filtering and persistence

Broad category selections are presentation filters, not new persisted preference fields. Continue from selected categories saves the current draft using the existing Interests step/revision, then shows concrete options after a successful save. A failure stays on the first screen and exposes the established recovery message. With no categories selected, Continue advances directly to Preferences, avoiding an empty screen; interests remain optional.

Concrete chips update the original `creativeInterests`, `readingFormats`, `readingGenres` and `readingTopics` arrays. Filtering never clears hidden saved choices. Continue from concrete choices uses the existing save to Preferences. On refresh the category screen opens and derives categories from saved concrete answers; category-only filters with no saved answers are not retained across refresh. Unsaved concrete selections are not persisted on each keystroke/toggle.

Back and Skip buttons are removed throughout at the user's request. Optional answers may remain blank and use Continue. The keyboard-only skip-to-main link remains an accessibility aid. Pending controls and errors retain their existing native/announced behavior; 401 and 409 recovery remain unchanged.

- Full-screen original archive/garden/horizon artwork, dark overlays and static fallback remain. No navigation/branding bar, footer, progress counter/line or explanatory subtitles.
- Question headings use existing Space Grotesk, 24px/1.35, semibold; Purpose uses 28px desktop and 26px mobile. Labels, chips and actions use the same supplied family with a restrained size hierarchy.

Purpose cards show short descriptions; starting-choice descriptions remain visually hidden accessible label text. - Desktop chips are at least 34px high. The single Continue/Finish action is 104px wide, at least 36px high, 13px regular text, the Google button's 10% white fill/20% white border and 8px backdrop blur. Chips use 8px blur. Flat fills remain usable when backdrop filtering is unsupported. Hover does not merge adjacent controls.
- On screens at most 767px or coarse pointers, choices/actions have at least 44px target height. Chip rows wrap and center; long content grows naturally and scrolls without a fixed-height form.
- Text inputs retain the shared login field recipe. Language now uses the same `LanguageDropdown` component as login (`components/ui/language-dropdown.tsx` and its CSS Module). The onboarding field shows English in full; login retains its compact EN trigger. Both share the dark 14px rounded popup, softly highlighted English / EN row and native details/summary behavior. Escape and selection restore trigger focus; outside clicks dismiss the popup. Option buttons explicitly use type=button so language selection never submits setup. English remains the only supported language; persistence contracts are unchanged.
- Existing 360ms question and 160ms field entrances run only under no-preference; reduced-motion CSS removes these and background crossfades.
