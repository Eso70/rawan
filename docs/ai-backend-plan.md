# Part 12 implementation plan

0. Inspect the actual API, worker, ownership, manuscript/search domains, queue contracts, configuration, tests and migration history. No existing AI adapter or generic BackgroundJob exists. Reuse the shared backend package, BullMQ, Prisma, JWT guards and isolated test schemas/prefixes.
1. Implement exactly BRAINSTORM, SUMMARIZE and REWRITE. All return text proposals. SUMMARIZE/REWRITE require supplied text or explicit selected content. Support Scene, Character, TimelineEvent, PlotPoint and Note; other domains/search remain available for future explicit selection.
2. Keep the domain in AiGeneration. Persist bounded instructions/text/resource IDs, normalized result, prompt version, usage and safe failure metadata. PostgreSQL is the durable source of truth. No canonical writes, application endpoint or cancellation in v1.
3. Add a new migration, enum lifecycle and project/user cascade relations. Index project listing, user creation limits, and pending recovery. Never alter historical migrations.
4. Use a small normalized provider interface with AbortSignal, central config and output validation. Initially implement only deterministic fake-v1: explicit development/test opt-in, prohibited in production. Disabled is the default. No credential is required, no SDK or paid network call is installed. Fake output is clearly labeled and is not presented as real AI intelligence. Unsupported provider/config is rejected.
5. Resolve selected IDs on both creation and execution, including owner and same-project constraints. SQL projects only bounded text fields; max eight resources, 4,000 characters/resource, 32,000 total context, 2,000 instructions and 8,000 supplied text. Report truncation. No auto-search, RAG or secrets.
6. Central task/version definitions and structured system/user messages isolate policy, author instructions and untrusted context. Bound output to 12,000 characters; enforce normalized text/usage. No arbitrary model/tool/system-prompt input.
7. One AI queue carries only version and generation UUID. Three transient attempts with exponential backoff. Durable pending rows are periodically republished, including recovery after Redis loss. Database execution leases with fencing prevent overlapping workers from committing conflicting results; completed/failed rows never invoke the provider again. Lease expiry permits crash recovery, bounded database attempt count prevents infinite retries. Exactly-once external charging cannot be guaranteed after a process crash; document this.
8. JWT-protected POST/list under projects and GET detail by generation ID. Whitelisted nested DTOs, pagination, ownership-scoped reads and explicit 202 queued response. Serialize creation limits with a user-row lock: five pending, 30/hour and 200/day, including across API replicas. Queue outage does not erase durable accepted requests.
9. Store only provider-reported tokens; fake reports null. Cost remains null without reliable pricing. Safe enumerated errors only; no prompts/results/keys in logs. Completed proposal includes provider/model/version and timestamps.
10. Deterministic provider/prompt/config/context/processor tests plus isolated real PostgreSQL/Redis HTTP integration covering ownership, same-author cross-project, lifecycle, retry, permanent failure, duplicates, overlap, recovery, usage and no canonical mutation. No paid calls.
11. Explicitly audit all 20 requested security/privacy questions and fix discovered flaws.
12. Run Prisma format/validate/generate/deploy/status, shared builds, focused tests, all root checks, HTTP and queue/database regressions sequentially where builds touch dist.
13. Document all 18 requested report areas, real-provider limitation and manual configuration. Preserve both empty frontend folders. Do not start Part 13.

Extension points: add task definitions and validated inputs, add one provider adapter behind the normalized interface, evolve context retrieval independently, and expose streaming later using the same generation identity.
