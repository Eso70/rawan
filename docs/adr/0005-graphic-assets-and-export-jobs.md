# ADR 0005: imported graphics, retained artifacts and bounded preparation jobs

Date: 12 October 2026. Status: Accepted and implemented. Covers A07/A12 and originally H2 N20–N23/N25.

ComicDocument is separate from prose. Pages/vertical segments reference immutable processed artwork versions, carry accessibility text/transcripts and optional consecutive two-page spread groups. Reading direction is explicit LTR/RTL; artwork is never mirrored. Page script components support action, dialogue, captions and SFX, with private character/place appearance associations. Authored guided panels use normalized ordered rectangles. Changing page artwork invalidates its panels; page/panel editing checks revisions. A graphic release copies pages, transcripts, ordering, spreads and panels, not private scripts or appearance IDs.

WorkAsset imports an owned private image into a separate retained original. Original import is limited to 10 MiB; work originals are bounded to 500 images/512 MiB. Worker decoding allows JPEG/PNG/WebP only, rejects animation and oversized dimensions/pixel counts, normalizes orientation, strips source metadata and creates FULL/DISPLAY/THUMBNAIL WebP renditions. Generated files are bounded independently. Public routes expose only approved rendition roles through an eligible release or deliberately public avatar, never original files or storage keys. Work covers are explicit metadata; published release assets retain their approved versions.

Reuse the existing private StorageProvider and UUID object keys. ArtifactBlob is a durable file registry whose parent references become null on deletion. Register file intent before writing, mark results ready only after a fenced completion, and retry orphan cleanup after a grace period. No database byte arrays, untracked public directory files or external source URLs are used. Account/work deletion removes access and leaves durable cleanup records. Deferred NO ACTION asset foreign keys allow a whole-work/account cascade to finish while preventing a referenced asset from disappearing alone. API asset deletion returns 409 while references exist.

Artwork/export jobs persist QUEUED/RUNNING/COMPLETED/FAILED states in PostgreSQL. The worker polls with atomic conditional leases, fences completion, recovers expired leases and caps attempts. Decoder/render failures are terminal and expose safe codes; corrected artwork is imported as a new version. Interrupted imports expire. Cleanup is retryable even after the owning records disappear. API and worker must use the same storage path and database.

Prose preparation supports actual TXT, escaped HTML and EPUB output from an explicitly selected owned immutable release snapshot, including DRAFT/WITHDRAWN releases for private preparation. EPUB includes a stored-first mimetype, container/package, contents navigation, ordered XHTML sections and footnote links. Results are owner-only downloads with no-store caching and safe server-chosen filenames. PDF rendering, native drawing/lettering, automatic panel detection, OCR, visual AI and distribution are not claimed.

The current single-worker loop bounds concurrent native processing. Horizontally scaled workers still claim jobs conditionally and clean idempotently; storage must be shared if API/worker run on different machines.
