## Verdict

**Ready to begin the dashboard development phase locally. No confirmed onboarding defect or failing onboarding check remains. This is not an unconditional production-release sign-off.**

Existing accounts bypass setup; newly created accounts complete the required purpose question and setup. No dashboard, product destination, account-preference editor or unrelated backend feature was implemented during this audit.

## Changes made during this audit

Only onboarding test coverage and documentation changed; no confirmed onboarding product bug was found.

- Extended `apps/api/test/email-signup-database-smoke.mjs` with three actual registration/verification/login/setup/completion/next-login journeys, contract validation, persisted-state checks and role/record-count assertions. Its printed check total increased from 45 to 81.
- Extended `apps/api/test/setup-routing-local-smoke.mjs` with a correctly signed expired token, cookie/response assertions, incomplete-account re-login, logout cookie clearing and completed-account next login. Its printed status/value check total increased from 42 to 51.
- Extended `apps/api/test/setup-database-smoke.mjs` to reject attempts to set roles, required/status/revision/version/completion fields, unknown steps and completion with null purpose.

The optional broader command was also run:

```powershell
$env:SETUP_FULL_REGRESSION = 'true'
node apps/api/test/run-setup-validation.mjs
Remove-Item Env:SETUP_FULL_REGRESSION
```

That aggregate run **failed** at the plot race described above. A separate local throwaway-database harness subsequently ran plot, organization, search, media and hardening successfully. Repeated success in isolation does not establish that the race is fixed. Existing PostgreSQL concurrent-query deprecation warnings and Redis 5.0.14.1/background cleanup warnings were observed; onboarding persisted successfully. Redis background jobs need the documented 6.2+ environment and are outside this change.

## Manual release follow-up

Use the [full manual walkthrough](onboarding-guide.md#manual-test-walkthrough) with separate test accounts, never by changing a real account's rollout classification. Before a production release:

1. Exercise actual external email request/delivery/verification and Google sign-in through configured provider callbacks, including first-time and returning users.
2. Supply the missing design skill if exact compliance is required; complete screen-reader, browser zoom and OS reduced-motion checks.
3. Investigate the intermittent plot concurrency failure in its own scope and obtain a stable full regression run.
4. Validate the production origin, HTTPS/cookies, policies and supported Redis environment separately. Current authentication configuration intentionally targets localhost.

These are verification/release follow-ups, not authorization to add dashboards or unrelated features. Dashboard development can begin with the tested onboarding contract and existing application shells.
