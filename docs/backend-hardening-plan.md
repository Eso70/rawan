## Execution phases

0–2: Inspect all domains/shared infrastructure/schema/migrations, maintain this severity inventory, establish plan. 3: auth/hash/JWT/abuse defenses. 4: map each owned read/mutation and both author/project matrices; patch any discovered bypass. 5: review composite association foreign keys/checks/unique indexes/cascades, serializable retries and reorder atomicity; add a new migration only if necessary. 6: bound parser/input/list and safe errors, preserve v1 shapes. 7: explicit AI summary select, bounded SQL/pool, actual EXPLAIN and N+1 review. 8: verify signature/file/key/symlink/disposition/cleanup security. 9: verify queue retries/retention/idempotency/Redis outages and independent worker shutdown cleanup. 10: verify explicit project-scoped AI context, prompt boundaries/timeouts/leases/recovery/privacy. 11: safe request correlation and failure metadata; secret scanning without printing values; dependency fixes. 12: close high-risk gaps and CI omissions. 13: Prisma format/validate/generate/status, frozen install, lint/typecheck/unit/HTTP/all DB/media/queue/AI/OpenAPI/build/audits with safe isolated infrastructure. 14: full 17-area report plus all 30 security questions and a candid release-candidate verdict.

Run focused verification after each meaningful category. Documentation evolves with discoveries and actual results. No production reset, historical migration edits, Redis flush, paid AI calls or arbitrary dependency/framework upgrades.

## Discoveries and completion

After implementation began, review additionally identified unbounded embedded association reads, cleanup being skipped after one worker drain failure, unnecessary repeated HTTP test listeners and the need to validate explicit ingress proxy IP/CIDR ranges. These were addressed within the original scope. A traced PostgreSQL warning originates in Prisma's transaction adapter; it remains documented compatibility debt rather than prompting an unrelated framework upgrade. All phases were executed; actual verification, compatibility changes and remaining risks are recorded in [backend-hardening-report.md](backend-hardening-report.md).
